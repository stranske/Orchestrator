# Private coding B diagnostic custody

This finite source successor starts at38365fbe. It does not recover or guess the missing V5 child refusal. It preserves that historical UNKNOWN and never replays the consumed namespace, runs a full proof, calls a provider/API, reads credentials/configuration or changes account/billing/security settings. Reader source is paused and unwritten. The agent-authored blanket no-credit veto is not introduced here.

The three reserved hunks are closer_dispatcher's private coding exception frame, closer_native_observer's bounded projection and separate observation record, and closer_runtime_binding's post-B/finalizer custody. Existing signed admission, lifecycle source-frame checks, worker validation, semantic delivery, coding terminal/C readers and their receipt schemas are unchanged.

The dispatcher replaces raw str(error) with closer-coding-worker-held/v1: a fixed held reason and exact stage/code diagnostic, execution_authorized=false and retry_authorized=false. Stage comes only from exact whitelisted worker code-object identity AND worker module globals in the actual exception traceback. Code is a fixed source-message enum for actual WorkerHeld traces, or a coarse fixed class category. Unknown exception messages, custom __str__, locals, filenames, paths and user content are never projected. This identifies a source refusal stage; it is not a new admission proof.

The parent accepts only a complete small typed held frame with exact keys, exact false authority values, fixed stage/code enums and no duplicate JSON keys. Other output yields no_typed_held_frame. It never stores arbitrary held reason text. Actual normalized stdout/stderr remain bounded as before. The new closer-native-coding-b-observation/v1 record stores exit code, supervised cleanup/group facts, original B-start/config identity, stream byte counts/digests and that bounded diagnostic. It uses the existing actual lifecycle retain closure (create-only HMAC record and readback), under the exact _observed_correction_b code/globals and cfg/done/witness object identities. No raw stdout/stderr or candidate is added to this record. Its schema and filename are separate from coding-b-delivery and terminal evidence. All authority/completion fields are false.

Observation is attempted before semantic delivery validation. A secondary observation-custody failure is retained as a fixed category in memory; it does not manufacture a signed reference. Delivery validation failure is separately retained instead of discarding done/witness. The actual B exit/finish facts can therefore reach run_native_round. A delivery failure prevents terminal receipt binding, keeps UNKNOWN (or an actual permission denial), and cannot grant C or coding terminal authority, even if a stale/partial semantic artifact exists. A missing queue is not converted into known B/queue completion. Final UNKNOWN preserves original bounded B diagnostic, observation failure if any, delivery failure, and the later terminal diagnostic as distinct fields. Transport cleanup terminality is not semantic completion.

Necessary tests are in-process only; no subprocess is planned. They exercise real early worker/root guard refusals, strict frame parsing/privacy, synthetic summary bounds, actual observation producer caller refusal, detached post-observation mechanics with failure-only injections, short-circuit refusal of terminal receipt binding and detached final UNKNOWN presentation. Detached AST slices deliberately do not execute an authentication prefix and are not signed-admission or source-producer positives. Every injected producer fails; no validator/authentication-success stub or old receipt is used. A synthetic complete stdout frame is parser data, not actual native observation. Independent source/test-definition review precedes execution. The later genuine observation record can be exercised only by a separately assigned fresh actual source root; no such root proof is assigned here.

The test command requires a NEW synthetic HOME and explicit ORCH_REDACT_SECRET_FILES='' before Python imports, with plugin autoload disabled. Only this dedicated file and a fresh isolated baseline comparison are proposed. No broad suite, floor change, model/provider process or native runtime query is included.
