# Muse terminal lifecycle component — not wired to Closer

This change publishes the source-resident Muse capture/parser component and its
reviewed typed terminal compatibility. It does not register Spark, add a role
record, install a native issuer, change dispatch/activation, or invoke a model.
A concrete reviewed original host admission is still required by the capture
interface. No production Closer route calls this new component on this base.

The dedicated component parser recognizes closed, joined `run.usage` metadata,
including typed non-null allowance data. These fields never establish quota,
account, subscription, billing or execution authority. The original run terminal
and its command/session joins remain mandatory; usage is never the answer.

The narrower data-only runtime allows the expected `model.meta.response` task
intent only with its exact typed command/run/session/task, model proposal,
scheduled idempotency, null parent/cancellation, not-applicable policy and complete
lifecycle joins. Tool results and other side effects remain refused. This resolves
a parser rejection seen on one genuine captured response; it does not alter that
immutable signed capability-false result or claim new native admission/enrollment.

The original retained 63,781-byte stream yields the same 1,610-byte final through
the reviewed parsers. Thinking is neither exported nor scored. Tests use synthetic
metadata and owned inert capture seams; source publication makes no provider call.
The larger optional native-issuer composition remains a separate local source
proposal and is intentionally not included here. Current main's dispatcher,
profiles, role qualification data and activation logic remain byte-identical.

The qualified production `adapters.py` is byte-identical to the base source.
The dark runtime imports its dedicated parser and pins that complete module's
source, preserving the existing Sonnet model/source qualification contract.
No historical observation, record, source witness or guard is retargeted.
