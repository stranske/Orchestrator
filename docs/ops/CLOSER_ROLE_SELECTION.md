# Guarded Closer role selection

`config/closer_role_selection.json` is the reviewed quality/scope candidate
filter consumed by the existing neutral router and the dispatcher's existing
preselection/direct-profile paths. It does not enroll a runtime, create a role
qualification record, rank model brands, or authorize an action.

The Sonnet V2 and Sol High IDs are already registered. Terra 6.1, Muse Spark 1.3,
and Composer's **default/no-effort request** have no matching reviewed registered
binding in this base. Their `profile_id: null` entries are deliberately not
wildcards: they cannot dispatch until Core reviews an exact profile binding and
its current runtime/source compatibility. Never substitute Terra 5.6, Muse
Wonder, or Composer High. Composer's no-effort semantics also require a versioned
profile/adapter representation; this change does not relax the existing
qualification identity grammar to manufacture one.

Vibe's observed configuration has a finished human-reviewed-diagnostic-only
verdict and is outside the automatic pool. Existing Low/Astra trial limits do
not become provider-wide prohibitions or cross-effort promotions. Evidence IDs
and SHA256s are portable references to the frozen review records; selection does
not fetch external evidence as runtime authority.

## Controller integration

The trusted host supplies `closer_category` to the existing route helpers or
`router.select_agent`. A model-reported subtype must never choose this category.
Existing exact named-question calls default to `named_proof`. Bounded semantic
calls have **no implicit ordinary-static default**: Core must select
`ordinary_static` only where its host packet-scope handling preserves protected
security/ownership/authority decisions. A missing, unknown, protected or
unsupported category returns the existing qualification/collection hold; it is
not labeled measured quota exhaustion.

The route still requires `roles.is_runtime_qualified`, a matching registered
identity, current transport/confinement, explicit operator caps, profile/pool
capacity and the original shared allocation. The role-scoped Sonnet V2 opt-in
never changes `requires_explicit_selection` in the global profile registry.
Quality eligibility alone produces no dispatch. A final runtime recheck that
loses every profile returns no assignment, including under a Codex operator pin;
it never falls back to an unprofiled generic worker. Model pins constrain the
requested model while preserving the exact qualified effort; they do not invent
a Medium profile to replace a qualified High profile.

Neutral priors, learned scores and existing capacity pacing remain the chooser.
For an explicitly independent review, the optional trusted
`independent_of_provider` input excludes that known provider group. Only the
reviewed first-party OpenAI/Anthropic groups currently satisfy this exclusion;
unknown groups cannot manufacture independence through a different CLI name.
If no admitted distinct group remains, that independent request holds. Ordinary
requests do not acquire a mandatory cross-family gate. Requested provider groups
are not attestations of model weights or served effort.

## Fallback and authority

- Before a process starts, an unavailable candidate can be reselected only
  through the same category and fresh existing runtime/capacity/budget admission.
- A completed but rejected answer is not repaired or promoted. Existing
  collection/independent-review handling remains the fallback; without terminal
  cleanup it is an execution hold.
- Unknown execution is never permission to repeat the operation, switch models,
  or reset its budget. Reconcile the existing operation first.
- Account, boundary and safety failures stop the affected route. Missing eligible
  candidates hold rather than silently substituting a weaker model or role.
- Model subtype/advice never registers a mechanical plan, clears protected
  authority, or supplies ACT/merge/completion permission.

`fallback_decision` is a pure description of these existing hold/reselection
choices, not an executor. The returned `closer_selection` metadata carries the
requirements and explicitly grants neither runtime enrollment nor action
authority. Core must retain its current source-owned collection, review,
selected-merge and action guards when integrating this configuration.
