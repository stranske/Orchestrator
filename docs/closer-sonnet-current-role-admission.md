# Current-source Sonnet named-role admission leaf

This is an inactive source preparation path for the already registered
`claude-sonnet-5-5-high-v2` profile. It does not install a qualification, change
profile defaults, enable another transport, or authorize a repository action.

The source entry is
`closer_claude_role_admission.run_current_source_public_qualification`. It accepts
only the declared public CSV canary PR 984, the unchanged issue 983 body, one
original CSV criterion, and current-producer retained codepatch evidence for the
isolated exporter. It rebuilds the normal named request and prompt; callers cannot
supply a prompt, model, provider, alternate auth supplier, or alternate callback.
A frozen actual input packet and normal execution review are still needed before
calling it. No native verifier NONPASS is fabricated by this transport canary.

The entry creates an immutable one-use intent before the attempted operation and
uses the original Claude account pool, actual broker, protected existing OAuth
borrowing, isolated native argv/environment, and observed starting/started/finished
callbacks. Bounds are one native turn, no retry or fallback, 64 KiB prompt/native
result, 16 KiB final, 4096 requested output tokens, at most 60 seconds for the
native invocation and 90 seconds for the source entry. A resource or native
uncertainty is retained rather than replayed. These are one-canary policy limits,
not a model-wide quality grade or a claim about billed quota.

The qualification operation has a reserved identity. Its opaque permit is valid
only in the source entry or protected readback receiver, on the original thread,
for the original operation and bounded lifetime. Production proof validation
rejects these operations even when a caller strips a qualification-only marker.
A report or Boolean cannot manufacture a permit. No permit is serialized.

`reviewed_record_proposal(report_ref)` reopens the original immutable intent and
physical provider result, rechecks the current producer/descriptor and accepted
scoped quality evidence, then reuses the real production parser, native proof
validator and named-response validator. The report must contain the expected
supported negative answer for the deliberately partial CSV code. This is a finite
transport/capability observation, not a new corpus or general semantic review.
An independent review of the real answer and native trace is still required.

The receiver returns the existing role-record schema with `status: pending_review`
and `expires_at: null`. It does not mutate `ROLE_QUALIFICATIONS`. Existing code has
no maximum production qualification lifetime; its only time rule is finite
`qualified_at <= now < expires_at`. Fixture durations such as 900 seconds are not
production policy. The receiver therefore accepts no caller-selected expiry and
does not silently refresh timestamps. Normal source enrollment review must choose
an explicit durable expiry that survives publication and CI, and insert the
reviewed record. The original canary completion remains the recorded observation
time. A pending row fails both ordinary and runtime qualification.

There is no descriptor self-hash cycle. The controlled descriptor includes this
driver, the existing native producer/parser/validator sources and the fixed role
selection policy. It excludes the role-registry module and profile-registry data.
Reviewed data insertion therefore does not change the descriptor; changing a
selected source does require a fresh exact callback proof. Historical quality
artifacts remain byte-identical and do not acquire current runtime credit.

Per-launch binary, OAuth-custody, confinement, capacity, pool, process and action
checks remain fresh. Native request identity is not proof of a served reasoning
level, current plan entitlement or subscription-only accounting. The canary does
not alter the API route used by production Verify.

## Current real-input prerequisite

At the frozen a715 base, `closer_dispatcher.requirements` recognizes only Markdown
heading sections. The unchanged issue 983 body uses the plain heading
`Tasks and acceptance criteria:`; the actual parser currently returns zero
criteria. Consequently the strict current request builder refuses this real CSV
criterion before any pool, OAuth or native call. The short `## Tasks` source used
in inert controls does not establish that this real-input seam works.

This leaf deliberately does not change the source body or parser. Before the
one actual canary, the existing source owner must resolve that inventory grammar
with a separately reviewed requirements-preserving change (or supply a genuine
admitted native finding using the corresponding supported named-finding path).
A changed selected parser source requires the final current descriptor and
packet to be rebuilt. No historical proof or answer is rebound to that source.
