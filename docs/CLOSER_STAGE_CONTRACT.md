# Closer stage contract

An open PR with current green checks, no unresolved review threads, no explicit
hold, a non-draft state and no merge conflict can reach the existing exact-head
merge guard. This screen asks whether the PR can be evaluated and merged; it does
not demand a completed post-merge acceptance report. Required core request bytes
and identity remain revision-bound. Free-form requests do not need invented task
or acceptance headings.

The merge guard re-reads current GitHub state, required checks and all review
thread pages, observes the review floor and pins the mutation to the expected
head. A Closer merge is deterministic and does not ask the low-cost evidence
interpreter to certify acceptance. Closer opts out of the optional immediate adversarial panel: the bound verifier
and existing post-response agents perform acceptance evaluation. This does not
promise a later invocation of that extra panel. The explicit adversarial panel
and its BLOCKED follow-up API remain available; other merge-guard callers retain
their existing defaults. Required runtime acceptance gates remain mandatory.

For finite runs, a confirmed merge can produce one causal singleton successor
for `post_merge_verify`. The successor uses normal PREPARE, canonical assignment,
leases, resource admission, queue and action guards. It retains predecessor
identity and receipts, requires a fresh merged observation at the same head and
does not copy ready/PASS state. An active verifier, existing request, changed
head, pause or dependency prevents duplicate dispatch. Failed or uncertain child
execution remains visible in the outer validation without replaying the merge.

Remote-only native effects may ignore broad repository/workspace fences inferred
solely from an unrelated incomplete historical row. Exact target, linked source,
branch, explicit unresolved intent and unaccounted reservation keys remain fences.
A merge qualifies only when its configured runtime acceptance gate requires no
local execution, rechecked immediately before mutation. Local repair and
command-capable adjudication keep the full resource scope. Malformed history
cannot qualify for narrowed scope.

After a merge-bound verification response, the existing agents evaluate complete
source acceptance and NON_PASS follow-up. Failed checks and concrete review
findings remain real per-PR blockers. Missing necessary input uses targeted
collection; optional enrichment does not become a universal premerge condition.
